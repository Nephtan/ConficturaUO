## Recommended boundary

FIX-02 already supplies the transaction. `Skills.TryGrant` independently sums bases, checks target/donor ownership, locks and caps, publishes the whole grant before callbacks, rejects nested grants and recomputes the cache afterward (`Data/System/Source/Skills.cs:1480-1569`). `SkillCheck.Gain:679` and XML `SetSkillBase:1529` already classify `PlayerMobile || Mobile.Player`; a false flag on a real PlayerMobile does not select their NPC branch. Preserve these repairs rather than creating another grant engine.

1. Make `Skills.Total` genuinely getter-only. Its only production assignment outside `Skills`' private bookkeeping is `Skill.BaseFixedPoint:572`. Replace that delta-from-cache update with a narrowly scoped core reconciliation operation: publish the clamped base, sum the existing skill slots without creating new skills, publish the total, then invoke the existing callbacks. Reconcile even on a raw no-op if the intended guarantee is that every setter attempt repairs accounting. This changes cache state only; retain raw staff/NPC/load base and cap semantics.
2. Keep the `Total` getter observational. Recomputing inside it would hide the existing FIX-01 `cached_total_mismatch` diagnostic (`PlayerMobile.cs:1809-1831`). Use independent/reconciled real total for `SkillCheck.CheckSkill`'s gain probability at206 as well as transaction enforcement. Do not rewrite the atrophy probability or clamp/delete real bases as an accounting repair.
3. Prefer cache-only repair at the safe, ordinary `TryGrant` entry, including an ultimately rejected request, so refusal cannot preserve a falsified cache indefinitely. Retain thread/reentrancy/owner guards before any mutation; invalid cross-thread/nested calls must remain side-effect-free. Do not change the return value or consume reward resources merely because the cache was repaired. Existing successful-transaction callback reconciliation remains necessary. Document this narrow accounting change in regression expectations separately from unchanged base/cap/lock/resource assertions.
4. In XML, guard the **resolved object and actual `PropertyInfo.Name` immediately before mutation**, including the public `InternalSetValue` entry before conversion/logging. Apply the same predicate at the two `SetPropertyObject` setters. Preserve the existing AccessLevel/StaffLevel restrictions and ordinary read access. Never cache a permission decision by type/property: a cached `Skill` property can next refer to an NPC or a player's skill.

Making `Total`'s setter merely private is insufficient: a public-get/private-set property still has `CanWrite == true`, and this full-trust reflection path invokes `PropertyInfo.SetValue`. Remove the setter rather than relying on that visibility change. A public-setter check (`GetSetMethod(false)`) can also make the XML boundary explicit; it does not replace instance-aware protection.

## Paths and meaningful acceptance

`SetPropertyValue` traverses nested/attachment objects, resolves cold or cached properties, and falls back to enumeration (`BaseXmlSpawner.cs:1291-1516`). Both branches enter the final setter, while `SKILL` has its own early return. `LookupPropertyInfo:4778-4848` caches only type/property metadata. `SetPropertyObject:1542-1663` currently accepts only exact Mobile-typed leaves, so it cannot directly write an integer/bool cap; its legitimate MOB/TRIGMOB reference assignments must remain usable. `GetPropertyValue:1874-1969` intentionally permits reads of protected properties.

Required focused cases, without replacing the accepted FIX-02 suite:

- Direct player/Skills/Skill targets; mixed-case names; `Skills.Alchemy.Base`, `Skills.Highest.BaseFixedPoint`, `Skills.Alchemy.Owner.Cap`, `Skills.Alchemy.Owner.Owner.Player`, `ControlMaster.Skills.Alchemy.Cap`, and `Backpack.RootParent.SkillsCap`. These exercise real ownership after navigation from a different root. Also use an attachment Mobile-reference alias. Do not claim unsupported indexed property syntax works merely because the parser strips brackets.
- Null-spawner fallback, first non-null-spawner lookup, warm cache, and NPC-to-player/player-to-NPC reuse of the same cached property. Call the public final setter directly with player objects and with a staff `from`; reject protected writes before invoking a setter. Existing AccessLevel/StaffLevel restrictions must still hold through direct calls.
- Actual `ApplyObjectStringProperties` lower-case fast path and upper-case keyword/fallback paths, literal `@` values, `INC` and `ApplyToProperty` copy assignments; all converge on the same final restriction (`BaseXmlSpawner.cs:1983-2019,2114-2175,3212,4681-4708`). Include MOB/TRIGMOB reference assignment followed by a protected nested write. This is per-property protection, not a newly promised all-or-nothing transaction over an entire multi-property action.
- Bounded positive SKILL success, exact-cap and individual-cap refusal, Up/Down/Locked targets, false player flag, no-op, reduction, malformed/NaN/infinite/overflow values, and existing NPC behavior. Assert independent full base sum plus caps/locks/stats/components/identity and resources, not only a success/error string.
- Corrupt low/high/negative cache, raw increase/decrease/clamp/no-op, rejected and successful grants, transfers and callbacks (including exceptions and reentrancy). Check total publication before callbacks, preservation of real over-cap bases, and unchanged probability inputs for valid state. FIX-01 diagnostics must still observe false flags/cache corruption before repair without wiping anything.
- Ordinary staff restoration, character creation, NPC initialization/clone and load remain deliberate exceptions. The checked-in `tests/SkillVerificationProtection.cs:114,119` directly assigns Total to inject corruption; a getter-only change requires a clearly declared test-only reflection adapter. Preserve the original baseline/failed evidence and every no-wipe assertion, rather than removing those cases.

The `Skills` version3 serializer writes the same cap, slot count and skill records; its total is reconstructed, and older versions consume/discard the legacy stored total (`Skills.cs:1777-1875`). Preserve all positional writes/reads and version/type names.
