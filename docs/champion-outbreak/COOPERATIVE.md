## Retained failures and repairs

- **001** never starts a role case: the generated48-byte helper password exceeds the legacy30-byte packet field, and the saved client password format also cannot be assumed to accept plain text. Fresh launchers read a24-byte generated test credential privately into explicit CLI arguments. No credential values enter public records.
- **002** connects both clients, but the new reader omitted the bounded retry used by existing status readers and stops on a transient missing-file observation during atomic publication. The observer also initially attempts host-process binding from the sandbox, returning access denied before any case request. Host-context binding and the existing share-delete/bounded-retry pattern fix the test tools. This was not an automatic approval rejection.
- **003** performs native healing but earns no support points: the fixture omitted Helper.Player=true, which normal CharacterCreation explicitly sets. The ledger correctly rejects the non-player source. Fresh results assert and record both flags. Gameplay attribution code is unchanged.
- **004** retains five successful cases and a bard timeout. Isolated005 also times out with a pending server target. Inspection of the copied ClassicAssist implementation shows WaitForTarget only registering future packet waits; an instant cursor can arrive first. Final006 polls actual Engine.TargetExists and records the actual client cursor before sending an ordinary Target response. The native skill packet uses the same constructor/sender as ClassicAssist's name command, with the shard's Peacemaking ID9. Server skill, target, range, clock and participation rules remain intact. Failed copies stay stopped and retain their errors; no failed bard receives credit.
